Throttle key: IPv6 sources collapse to their /64 prefix, IPv4 unchanged, IPv4-mapped IPv6 keyed as the IPv4 address, anything unparseable falls back to the raw text (never raises); still salted SHA-256, helper still not callable by API roles. New index on `public_link_attempts (window_start)`. (103000 also stopped creating per-source rows once the breaker opened; that removed the per-source cap for fresh sources and was corrected the same day, see next entry.) `submit_public_decision` rejects a raw comment longer than 8000 characters (result `validation`) before the trim regex. Developer pgTAP 120/120.
- 2026-11-18: Correction `20261117104000_throttle_breaker_cap` (applied as `throttle_breaker_cap`). Review found that 103000 let a fresh source make unlimited misses while the breaker was open. Final throttle design: while global failures < hard cap 5000 (new `hard_cap` in `_throttle_limits()`), per-source rows and the 20-per-window cap work as originally (breaker at 1000 holds back sources that already failed); at global >= 5000 no new per-source rows are inserted, only the global row counts, and `_throttle_blocked` is true for every source for the rest of the window (rows bounded to about the cap per window, no unlimited source). Availability trade-off: during lockdown even valid-token requests get rate_limited (max 10 minutes), because the block precedes the token lookup; lookup order is SEC-5-2 and unchanged. Developer pgTAP 120/120 (the wrong breaker assertion restored; tests added for fresh source with breaker open, 20 cap below 1000, hard cap lockdown, `hard_cap` value). Tester 157/157.
