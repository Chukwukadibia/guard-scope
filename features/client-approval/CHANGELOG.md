- 2026-11-18: Security review fixes SEC-5-1 (MEDIUM) and SEC-5-8 (LOW; ISS-027, ISS-028) in forward migration `20261117103000_throttle_hardening` (applied to dev as `throttle_hardening`). Throttle key: IPv6 sources collapse to their /64 prefix, IPv4 unchanged, IPv4-mapped IPv6 keyed as the IPv4 address, anything unparseable falls back to the raw text (never raises); still salted SHA-256, helper still not callable by API roles. New index on `public_link_attempts (window_start)`. Cleanup on every failure call deletes at most 50 rows older than 1 day via that index, inside an exception block so it cannot fail the failure record. (103000 also stopped creating per-source rows once the breaker opened; that removed the per-source cap for fresh sources and was corrected the same day, see next entry.) `submit_public_decision` rejects a raw comment longer than 8000 characters (result `validation`) before the trim regex. Developer pgTAP 120/120.
- 2026-11-18: Correction `20261117104000_throttle_breaker_cap` (applied as `throttle_breaker_cap`). Review found that 103000 let a fresh source make unlimited misses while the breaker was open. Final throttle design: while global failures < hard cap 5000 (new `hard_cap` in `_throttle_limits()`), per-source rows and the 20-per-window cap work as originally (breaker at 1000 holds back sources that already failed); at global >= 5000 no new per-source rows are inserted, only the global row counts, and `_throttle_blocked` is true for every source for the rest of the window (rows bounded to about the cap per window, no unlimited source). Availability trade-off: during lockdown even valid-token requests get rate_limited (max 10 minutes), because the block precedes the token lookup; lookup order is SEC-5-2 and unchanged. Developer pgTAP 120/120 (the wrong breaker assertion restored; tests added for fresh source with breaker open, 20 cap below 1000, hard cap lockdown, `hard_cap` value). Tester 157/157. Advisors: only documented dispositions.
- 2026-11-19: Token-first throttle (HA-009 / DEC-015; fixes Tester F-7 and SEC-5-2; ISS-029) in forward migration `20261119100000_token_first_throttle` (applied as `token_first_throttle`). `get_public_proposal` and `submit_public_decision` now run the cheap input checks, then look up `token_hash`; a found token is always processed whatever the per-source, breaker or hard-cap state. A miss (bad format or not found) checks `_throttle_blocked` first: blocked returns rate_limited and is not recorded, otherwise it is recorded and returns invalid. In submit, the SEC-5-8 raw-length bound and the decision/comment validation still run before the lookup (validation errors are never counted). Lock order, idempotency, link states, /64 keying, hard cap (lockdown of misses only) and bounded cleanup are unchanged. Frontend unchanged: rate_limited still occurs for misses and gateway 429s; the copy stays. Developer pgTAP 136/136 (changed: #48 and #55 now expect a served correct token, #49 now checks a correct-token decision plus a rate_limited miss on submit; 14 added for served-at-block/breaker/hard-cap and unrecorded blocked misses). Tester assertions that encoded the old order and now fail only because of it: 'at 20 recorded failures the source is blocked, even for a known token', 'blocked source: submit is blocked before any validation', 'blocked source gets rate_limited even for malformed submit input' (malformed input is validated before the lookup), 'global breaker at 1000 holds back sources that already failed', S14, S18, S21, S25, S26, S30 (the submit is now recorded), S40 and S45 (tk(96) is already decided by S26).
